# 서비스 기획서 — AXISOLVE Writing Engine

작성일: 2026-08-24

---

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | AXISOLVE Writing Engine |
| 한 줄 정의 | 주제를 고르면 학년 기준에 맞는 영어 에세이 모범 답안을 AI가 써 주는 웹 서비스 |
| 타겟 | 초등 영어 라이팅을 지도하는 학원 강사, 라이팅 과제를 준비하는 초등 3~6학년 학습자 |
| 배포 형태 | 정적 프론트엔드 + 서버리스 함수 1개 (Vercel) |

## 2. 문제 정의

초등 영어 라이팅 수업에서 강사가 겪는 병목은 "주제"가 아니라 **"학년 기준에 맞는 모범 답안"** 입니다.

1. 실전 주제는 이미 학원마다 축적되어 있지만, 학년별 모범 답안은 매번 강사가 직접 씁니다.
2. 일반 AI 챗봇에 주제를 넣으면 글은 나오지만 **분량과 문단 구조가 학년 기준과 어긋납니다.**
   초1-2에게 200단어 4문단 에세이가 나오거나, 초5-6에게 축약형이 섞인 구어체 글이 나옵니다.
3. 결과를 사람이 일일이 세어 보고 다시 요청해야 하므로, 결국 시간이 절약되지 않습니다.

## 3. 해결 방식

**"생성"이 아니라 "기준 통과까지 생성"** 으로 문제를 바꿉니다.

1. 학년별 합격 기준을 코드에 상수로 고정합니다.
2. AI 응답을 받은 즉시 브라우저가 단어 수·문장 수·문단 수·축약형을 기계적으로 검사합니다.
3. 미달 항목을 문장으로 만들어 프롬프트에 되먹이고, **최대 4회까지 자동으로 다시 씁니다.**
4. 4회 모두 미달이면 가장 근접한 결과를 보여 주고 경고를 표시합니다. (조용히 실패하지 않습니다.)

### 학년별 합격 기준

| 학년 그룹 | 분량 | 구조 | 문법·격식 |
|---|---|---|---|
| 초1-2 | 60~80단어 / 5~7문장 | 한 문단 | 단문 위주, 축약형 허용 |
| 초3-4 | 100~130단어 | 한 문단 (Topic → Support → Closing) | 단문·복문 혼합 |
| 초5-6 | 180~220단어 | 정확히 4문단 (Intro / Body 1 / Body 2 / Conclusion) | 포멀, 축약형 금지 |

## 4. 화면 구성

| 섹션 | 목적 | 주요 요소 |
|---|---|---|
| 소개 (`#home`) | 서비스 가치 전달 | 히어로 문구, 지표 4종, 핵심 기능 카드 3종 |
| 에세이 생성 (`#generator`) | 핵심 기능 | 주제 사이드바(검색·영역 5종), 학년 탭, 생성 버튼, 결과 패널 |
| 사용법·FAQ (`#about`) | 진입 장벽 제거 | 4단계 사용법, FAQ 5문항 |

## 5. AI 기능 상세

```
[사용자]  주제 선택 + 학년 선택 + 키워드(선택)
   │
   ▼
[브라우저] 학년별 프롬프트 조립 (분량 규칙 + 출력 JSON 스키마)
   │  POST /api/generate  { prompt, system }
   ▼
[서버 함수 api/generate.py]  OPENAI_API_KEY 로 OpenAI Responses API 호출
   │
   ▼
[브라우저] JSON 파싱 → 기준 검증 → 미달 시 피드백 붙여 재요청 (최대 4회)
   │
   ▼
[화면]  브레인스토밍 · 아웃라인 · 어휘/문형 · 에세이 본문  +  localStorage 저장
```

- **입력 검증**: 주제 미선택 시 생성 불가. 프롬프트 20,000자 초과 시 서버가 거절.
- **출력 형식**: 학년마다 다른 JSON 스키마를 프롬프트에 명시하고, 응답에서 JSON 블록만 추출.
- **결과 보존**: 주제 번호를 키로 localStorage에 저장 → 새로고침해도 유지.
- **내보내기**: 교재 제작 파이프라인이 요구하는 스키마(`topic_no`, `area`, `topic`, `grades`)로 JSON 다운로드.

## 6. 기술 스택 및 보안

| 계층 | 선택 | 사유 |
|---|---|---|
| 프론트엔드 | 바닐라 HTML/CSS/JS | 빌드 단계 없음 → 정적 호스팅에 그대로 배포 |
| 백엔드 | Vercel Python Serverless (`api/generate.py`) | 함수 1개면 충분, 상시 서버 불필요 |
| AI | OpenAI Responses API | 긴 지시문·JSON 스키마 준수에 적합 |
| 상태 저장 | 브라우저 localStorage | 서버에 학생 결과물을 남기지 않음 |

**API 키 취급** — 키는 Vercel 환경변수에만 존재합니다. 브라우저 번들, 네트워크 응답,
저장소 어디에도 포함되지 않으며, 프론트엔드는 같은 도메인의 `/api/generate` 만 호출합니다.

## 7. 예외 처리 설계

| 구분 | 상황 | 처리 |
|---|---|---|
| 입력 | 주제 미선택 | 안내 문구 표시, 생성 차단 |
| 입력 | 키워드 공란 | 정상 진행 (AI가 소재 선정) |
| 진행 | 생성 중 | 버튼 잠금 + 시도 횟수 표시 |
| 서버 | 키 미설정 | 500 — 설정 방법 안내 문구 |
| 서버 | 호출량 초과 | 429 — 재시도 안내 |
| 서버 | 연결 실패 | 504 — 네트워크 확인 안내 |
| 응답 | JSON 파싱 실패 | 자동 재시도 대상으로 처리 |
| 품질 | 4회 재시도 후에도 미달 | 최근접 결과 + 경고 배지 |

## 8. 범위에서 제외한 것

- 로그인·사용자 계정 (배포 후 접근 제한이 필요하면 별도 추가)
- 학생 답안 첨삭 (현재는 모범 답안 생성 전용)
- 서버 측 결과 저장 및 통계
