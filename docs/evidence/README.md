# 증빙 자료

과제 2절 제출 패키지 5번 항목입니다. 두 세트가 필요합니다.

1. 서비스 스크린샷 — **데스크톱 + 모바일 + AI 기능 동작 장면** → `screenshots/` (01~13 완료)
2. AI 코딩 도구 사용 과정 — 대화 로그 또는 스크린샷 → [ai-tool-log.md](ai-tool-log.md)

> 이 폴더는 `.vercelignore` 의 `docs/` 규칙에 따라 **배포본에 올라가지 않습니다.**
> 저장소에는 남고 서비스 주소로는 열리지 않습니다.

## 0. 어떻게 찍었는가

전부 **배포된 주소**(`https://axisolve-writing-assignment.vercel.app`)를 상대로 찍었습니다.
로컬 화면이 아닙니다.

Chrome 151 을 헤드리스로 띄우고 DevTools Protocol 로 직접 몰았습니다.
사람이 캡처 키를 누르는 것과 같은 화면이되, 화면 크기가 정확히 기록됩니다.

```
Emulation.setDeviceMetricsOverride   화면 크기 고정 (deviceScaleFactor 2 — 2배 해상도)
Emulation.setUserAgentOverride       모바일은 iOS Safari UA
Page.captureScreenshot               캡처 (긴 페이지는 captureBeyondViewport)
```

**가로 스크롤 여부를 매 장 함께 측정했습니다.** 1440·390 폭 전부 `0px` 였습니다.
반응형이 깨지지 않았다는 뜻이며, 이것이 과제 4-4 항의 근거입니다.

실패 처리 세 장은 이렇게 만들었습니다.

| 장면 | 만든 방법 | 유료 호출 |
|---|---|---|
| 11 빈 입력 | 직접 입력 폼에 한 글자만 넣고 제출 | 없음 |
| 12 오프라인 | `Network.emulateNetworkConditions { offline: true }` | 없음 |
| 13 지연 안내 | `Fetch.enable` 로 `/api/generate` 요청을 붙잡아 둠 | **없음** (서버로 나가지 않음) |

13 은 DevTools 의 `Slow 3G` 로 만드는 것과 같은 성격의 조작입니다.
요청을 붙잡아 두는 쪽이 20초라는 시점을 정확히 재현할 수 있고 과금도 없습니다.

09·10 만 **실제 생성**입니다. 가장 원가가 낮은 Grade 1-2 로 한 번만 돌렸습니다.

## 2. 찍는 방법

**모바일 화면** — 실제 휴대폰으로 찍어도 되지만, 크기를 명확히 남기려면 개발자도구가 낫습니다.

```
Chrome 에서 배포 URL 접속
  → F12 (개발자도구)
  → Ctrl + Shift + M (기기 도구 모드)
  → 상단에서 iPhone 14 선택 (390 × 844)
  → Ctrl + Shift + P → "Capture screenshot" 입력 → 실행
```

`Capture full size screenshot` 을 쓰면 스크롤 전체가 한 장으로 나옵니다.
랜딩(`#home`)은 길어서 이쪽이 보기 좋습니다.

**데스크톱 화면** — 브라우저 창을 1440 폭 이상으로 키우고 같은 방법으로 찍습니다.

## 3. 반드시 지킬 것

- **주소창이 보이게** 찍으십시오. 배포 URL 에서 찍었다는 증거가 됩니다.
- 개발자도구 Network 탭이 열린 장면이라면 **요청 헤더에 키가 없는지** 먼저 확인하십시오.
  이 서비스는 브라우저가 `/api/generate` 만 부르므로 키가 나올 일이 없지만, 습관이 중요합니다.
- 로그인한 화면을 찍는다면 이메일·전화번호 같은 개인정보를 가리십시오.
- 파일 형식은 PNG. 이름은 위 표 그대로 (번호 순서가 제출 순서입니다).
