# 항목 1 — 확인 사항

## 1-1. 배포 URL 로 접속 가능하고, 최소 3개 이상의 페이지/섹션이 메뉴 이동으로 확인되는가?

**예. 4개입니다.**

| 해시 | 섹션 | 내용 |
|---|---|---|
| `#home` | 소개 | 히어로 · 4대 채점 루브릭 · 학년별 기준표 · 자가진단 · CTA |
| `#generator` | 에세이 생성 | 주제 사이드바 · 학년 탭 · 결과 패널 |
| `#pricing` | 요금제 | 상품 4종 · 충전 코드 등록 |
| `#about` | 사용법·FAQ | 4단계 사용법 · FAQ 10문항 |

이동 방식은 `location.hash` 라우팅입니다(`nav.js`, 32줄). 상단 링크에 `data-nav` 를 달고,
현재 섹션에만 `is-active` 클래스와 `aria-current="page"` 를 붙입니다.
페이지를 새로 받지 않으므로 이동이 즉시이고, 뒤로 가기도 그대로 동작하며,
각 섹션의 주소를 따로 공유할 수 있습니다. 없는 해시는 `#home` 으로 떨어집니다.

여기에 법적 고지 3장(`privacy.html` `terms.html` `refund.html`)이 별도 문서로 있습니다.

**근거** — `docs/evidence/screenshots/01`~`04`

## 1-2. 모바일에서 레이아웃이 깨지지 않고 정상 동작하는가(반응형)?

**예. 측정값으로 확인했습니다.**

배포 주소를 1440×900 과 390×844(iPhone 14) 로 열어 매 화면마다
**가로 넘침(`scrollWidth - clientWidth`)을 쟀고 전부 `0px`** 였습니다.

| 화면 | 폭 | 가로 넘침 |
|---|---|---|
| `#home` `#generator` `#pricing` `#about` | 1440 | `0px` |
| `#home` `#generator` `#pricing` | 390 | `0px` |

390 폭에서 실제로 바뀌는 것:

- 생성기의 주제 사이드바가 **위로 접히고** 결과 패널이 아래로 내려갑니다 (`max-width:820px`)
- 요금제 카드가 **1열**로 (`max-width:560px`), 루브릭 카드도 1열로
- 학년 기준표가 가로 스크롤 없이 접힙니다

중단점은 `styles.css` 에 820·720·640·520px, `landing.css` 에 1000·980·900·720·620·560px 입니다.

## 1-3. AI 기능이 "입력 → 요청 → 결과 표시" 까지 정상 동작하는가?

**입력과 요청까지는 동작합니다. 결과 표시가 지금 막혀 있습니다.**

배포본에 **`OPENAI_API_KEY` 환경변수가 설정되어 있지 않습니다.**
생성 버튼을 누르면 서버가 다음을 돌려줍니다.

```
HTTP 500
{"error": "OPENAI_API_KEY 가 설정되지 않았습니다.
           Vercel 프로젝트의 Settings > Environment Variables 에서 추가한 뒤 재배포해 주십시오."}
```

**이것은 코드 결함이 아니라 배포 설정 누락입니다.** 근거를 셋 댑니다.

1. 서버 코드는 키가 없을 때를 **의도적으로 처리하고 있습니다.** 그래서 500 과 함께
   무엇을 어디서 고치라는 문장이 나옵니다(`api/generate.py`). 안 다룬 코드였다면
   스택 트레이스가 그대로 노출됐을 것입니다.
2. 같은 코드를 로컬에서 키와 함께 돌리면 정상 생성됩니다.
3. 나머지 함수 4개(`/api/topics` `/api/me` `/api/pdf` `/api/redeem`)는 배포본에서
   정상 응답합니다. 파이썬 런타임과 라우팅은 문제가 없다는 뜻입니다.

**조치** — Vercel > Settings > Environment Variables 에 `OPENAI_API_KEY` 를 넣고 **Redeploy**.
환경변수는 재배포 시점에 함수로 전달되므로, 값만 넣고 재배포하지 않으면 반영되지 않습니다.

**근거** — `docs/evidence/screenshots/08-ai-input.png`(입력 화면),
`14-fail-apikey.png`(현재 상태), `docs/test-cases.md` E2-9

## 1-4. 정상/빈값/긴 입력 등 2~3개 테스트 입력으로 동작이 재현 가능한가?

**예. 빈값·긴 입력·잘못된 형식 세 가지를 배포본에서 재현했습니다.**

| 입력 | 명령 | 응답 |
|---|---|---|
| 빈값 | `-d '{"prompt":"","system":"t"}'` | `400` `{"error": "생성 요청이 비어 있습니다. 주제를 선택한 뒤 다시 시도해 주십시오."}` |
| 20,001자 | 긴 문자열 | `400` `{"error": "요청이 너무 깁니다. 키워드를 줄인 뒤 다시 시도해 주십시오."}` |
| JSON 아님 | `-d 'not json'` | `400` `{"error": "요청 형식이 올바르지 않습니다. (JSON 파싱 실패)"}` |

브라우저 쪽에서도 같은 것을 막습니다. 직접 입력 주제가 2자 미만이면 요청 자체가
나가지 않고 폼에 "주제를 입력해 주십시오." 가 뜹니다.

**서버와 브라우저 양쪽에서 검사하는 이유** — 브라우저 검사는 사용자를 위한 것이고
(요청을 아끼고 즉시 알려 줌), 서버 검사는 시스템을 위한 것입니다. 브라우저 검사는
개발자도구로 우회할 수 있으므로, 서버가 다시 검사하지 않으면 방어가 없는 것과 같습니다.

정상 입력은 1-3 의 키 문제로 현재 재현되지 않습니다. 키를 넣으면 됩니다.

**근거** — `docs/test-cases.md` B절 · `docs/evidence/screenshots/11-fail-empty.png`

**예. 요구는 1개 이상인데 네 가지가 구현되어 있고, 넷 다 화면으로 찍었습니다.**

`13-fail-slow.png` 한 장에 스피너·버튼 잠금·시도 표시 `1/4`·지연 안내가 함께 잡혀 있습니다.

## 1-6. API 키가 코드에 노출되지 않았고, 환경 변수로만 관리되는가?

**예.**

```bash
git grep -nE "sk-[A-Za-z0-9]{20,}"      # 결과 없음
git log -p --all | grep -cE "sk-[A-Za-z0-9]{20,}"   # 0 — 과거 이력에도 없음
```

키가 없는 곳과 있는 곳:

| 장소 | 키 | 왜 |
|---|---|---|
| Git 저장소 | ❌ | `.gitignore` 에 `.env` `.env.local` |
| 브라우저로 내려가는 파일 | ❌ | 프론트는 `/api/generate` 만 부른다. OpenAI 주소를 모른다 |
| API 응답 본문 | ❌ | 서버는 `{"text": ...}` 만 돌려준다 |
| **Vercel 환경변수** | ✅ | 함수 실행 시에만 `os.environ` 으로 읽는다 |

`.env.example` 은 저장소에 있지만 값이 `sk-...` 자리표시자입니다.
**필요한 키의 이름과 의미만 알려 주고 값은 주지 않기** 위해서입니다.

> **다만 하나 짚어 둡니다.** 키를 숨기는 것과 **엔드포인트를 잠그는 것은 다른 일**입니다.
> 현재 배포본에 `ALLOWED_ORIGINS` 가 설정되어 있지 않아, 브라우저가 아닌 곳에서도
> `/api/generate` 를 부를 수 있습니다. 키는 안 새지만 **호출은 남이 할 수 있고 요금은
> 제 계정으로 나옵니다.** 1-3 의 키와 함께 넣고 재배포해야 합니다.
> 코드는 이미 이 검사를 하고 있습니다(`api/_guard.py`). 값만 비어 있습니다.

# 항목 2 — 구조와 처리에 대한 설명

## 2-1. `html / css / js / api` 구조를 왜 이렇게 나눴는지 설명할 수 있는가?

**나눈 기준은 "무엇이 바뀔 때 같이 바뀌는가" 입니다.**

```
index.html          무엇이 있는가        ← 구조가 바뀔 때만 바뀐다
styles.css          생성기 화면의 모양
landing.css         랜딩·요금제의 모양   ← 성격이 달라 파일을 갈랐다
legal.css           법적 고지의 모양
nav.js              섹션 전환            ← app.js 와 서로 참조하지 않는다
app.js              생성 기능 전체
landing.js          자가진단·충전 문의
auth.js             카카오 로그인
api/*.py            서버에서만 할 일     ← 브라우저에 내려가면 안 되는 것
```

**CSS 를 셋으로 나눈 이유** — 생성기는 어두운 작업 화면이고 랜딩은 밝은 배경입니다.
색 체계가 아예 달라 한 파일에 두면 서로의 변수를 덮어씁니다.

**`nav.js` 를 `app.js` 에서 뗀 이유** — 섹션 전환은 생성 기능과 아무 상관이 없습니다.
실제로 두 파일은 서로의 함수를 한 번도 부르지 않습니다. `app.js` 가 오류로 죽어도
섹션 이동은 계속 됩니다.

**`api/` 를 가른 기준이 가장 중요합니다.** 여기 들어가는 것은
**"브라우저가 보면 안 되는 것"** 입니다.

| 브라우저에 있는 것 | `api/` 에 있는 것 |
|---|---|
| 화면, 상태, 검증 규칙 | API 키 |
| 무엇을 요청할지 | 출제 학원명 (`_topics_full.py`) |
| 결과를 어떻게 보여줄지 | 크레딧 차감·환불 |
| | 레이트리밋 카운터 |

특히 워크북 PDF 는 **서버에서 만듭니다.** 헤더에 출제 학원명이 찍히기 때문입니다.
브라우저에서 만들면 학원명을 브라우저로 내려보내야 하고, 그러면 자산이 노출됩니다.
같은 이유로 `/api/pdf` 는 브라우저가 보낸 학원명을 믿지 않고 `topic_no` 로
서버 DB 를 다시 조회해 덮어씁니다.

`api/` 안에서 `_` 로 시작하는 파일은 **주소가 없는 공용 모듈**입니다.
`vercel.json` 의 rewrites 로 `/api/_*` 를 404 로 막았습니다. 안 막으면 서버 코드가 읽힙니다.

**프레임워크를 안 쓴 이유** — 빌드 단계가 없으면 정적 호스팅에 그대로 올라가고,
"내가 쓴 파일"과 "브라우저가 받는 파일"이 같아 디버깅에 번들 해석이 끼지 않습니다.
지금 규모(프론트 약 1,400줄)에서는 상태 관리 라이브러리가 해결할 문제가 없습니다.

## 2-2. AI 기능의 프론트 로직에서 "로딩 / 성공 / 실패" 상태를 어떻게 처리했는지 설명할 수 있는가?

상태를 **세 개의 변수**로 들고, 바뀔 때마다 화면을 다시 그립니다.

```javascript
loadingInfo[grade] = { attempt: 1, max: 4, slow: false }   // 로딩 (학년마다 따로)
doc.grades[grade]  = { ...생성 결과 }                       // 성공
errorMsg           = "…"                                    // 실패
```

**로딩** — 학년마다 따로 둡니다. Grade 1-2 를 생성하는 동안 Grade 3-4 탭을 눌러도
그쪽은 멀쩡히 보여야 하기 때문입니다. 로딩 중에는 버튼이 잠기고, `attempt` 가 2 이상이면
라벨이 `(재시도 2/4)` 로 바뀝니다. `slow` 는 20초가 지나면 켜집니다.

**순서가 중요합니다.** 요청을 보내기 **전에** 상태를 바꾸고 다시 그립니다.

```javascript
loadingInfo[grade] = { attempt: 1, max: MAX_ATTEMPTS };
renderMain();                       // ← 먼저 그린다
const result = await generateWithRetry(...);   // ← 그다음 요청
```

`await` 는 브라우저를 멈추지 않습니다. 먼저 그려 두지 않으면 화면은 아무 일도 없는 것처럼
보이고, 사용자는 한 번 더 누릅니다. **유료 API 가 두 번 나갑니다.**

**성공** — 결과를 `doc.grades[grade]` 에 넣고 `localStorage` 에도 저장합니다.
새로고침해도 남습니다. 그리고 여기가 이 서비스의 특징인데, **성공을 그냥 성공으로
받지 않습니다.** 단어 수·문장 수·문단 수·축약형을 세어 학년 기준에 맞는지 검사하고,
미달이면 부족한 항목을 프롬프트에 붙여 다시 요청합니다(최대 4회).
4회 후에도 미달이면 **가장 근접한 결과에 경고를 붙여** 보여 줍니다.

**실패는 세 갈래로 갈랐습니다.** 갈라야 대응이 다르기 때문입니다.

| 갈래 | 처리 | 왜 |
|---|---|---|
| 재시도로 풀릴 것 (JSON 파싱 실패, 일시 오류) | 루프 안에서 삼키고 다음 시도 | 사용자에게 보여 봐야 할 일이 없다 |
| 재시도해도 같을 것 (401 로그인, 402 크레딧) | 루프를 **즉시** 중단하고 안내창 | 4번 더 눌러 봐야 4번 다 401 이다 |
| 그 밖의 오류 | `errorMsg` 에 담아 빨간 상자로 | |

401·402 는 `billingError()` 로 표시를 붙여 던집니다. 이때는 빨간 오류 상자를
**띄우지 않고** 로그인·충전 안내창을 엽니다. "오류가 났다" 가 아니라
"이걸 하면 됩니다" 로 보여야 하기 때문입니다.

마지막으로 `finally` 에서 로딩 상태를 반드시 지웁니다. 성공하든 실패하든
버튼이 잠긴 채 남으면 사용자가 아무것도 못 합니다.

## 2-3. Serverless Function(Python)에서 입력 검증과 응답 포맷을 어떻게 정했는지 설명할 수 있는가?

### 입력 검증 — 싼 검사부터, 비싼 일 전에

```
① JSON 파싱          실패 → 400
② prompt 타입·빈값    실패 → 400
③ prompt 길이 20,000자 초과 → 400
④ OPENAI_API_KEY 존재 → 없으면 500
⑤ 출처 검증 + 레이트리밋 (_guard)   → 403 / 429 / 503
⑥ 로그인·크레딧 확인 (_supabase)    → 401 / 402
⑦ ────────── 여기서부터 돈이 든다 ──────────
⑧ OpenAI 호출
```

**순서가 곧 설계입니다.** ①~⑥ 은 전부 **OpenAI 를 부르기 전에** 끝납니다.
비싼 일(⑧) 앞에 공짜 검사를 다 몰아넣는 것이 원칙입니다.
길이 검사를 뒤로 미루면, 20만 자짜리 프롬프트를 그대로 모델에 보내고 요금을 낸 뒤에
거절하게 됩니다.

`_` 로 시작하는 공용 모듈로 뺀 이유도 같습니다. `_guard` 는 `/api/generate` 뿐 아니라
`/api/pdf` `/api/topics` `/api/redeem` 도 씁니다. 방어를 한 곳에 모아야 빠뜨리지 않습니다.

### 응답 포맷 — 두 가지 모양뿐

```json
성공  { "text": "모델이 생성한 원문", "credits": 12 }
실패  { "error": "사용자에게 그대로 보여 줄 한국어 문장" }
```

정한 규칙이 셋 있습니다.

**1. `error` 는 항상 사용자에게 그대로 보여 줄 수 있는 문장입니다.**
`"invalid_request"` 같은 코드가 아닙니다. 프론트가 오류 코드를 한국어로 번역하는
표를 따로 들고 있으면, 서버에 새 오류가 생길 때마다 프론트도 같이 고쳐야 하고
빠뜨리면 사용자는 영어 코드를 보게 됩니다.

**2. 스택 트레이스를 그대로 내보내지 않습니다.** 파일 경로와 코드 구조가 새고,
사용자는 어차피 못 읽습니다. 대신 **무엇을 어디서 고치라**를 적습니다 —
"OPENAI_API_KEY 가 설정되지 않았습니다. Vercel 프로젝트의 Settings > Environment
Variables 에서 추가한 뒤 재배포해 주십시오."

**3. HTTP 상태 코드를 실제 의미대로 씁니다.** 프론트가 코드만 보고 갈래를 나눌 수
있어야 하기 때문입니다.

| 코드 | 의미 | 프론트의 반응 |
|---|---|---|
| 400 | 요청이 잘못됨 | 그대로 표시 |
| 401 | 로그인 필요 | **로그인 안내창** |
| 402 | 크레딧 부족 | **충전 안내창** |
| 403 | 허용되지 않은 출처 | 그대로 표시 |
| 429 | 호출량 초과 (+`Retry-After`) | 그대로 표시 |
| 500 | 서버 설정 문제 | 그대로 표시 |
| 502 | 응답이 잘림 | **자동 재시도** |
| 503 | 전역 상한 도달 | 그대로 표시 |
| 504 | AI 서버에 못 닿음 | 그대로 표시 |

401 과 402 를 400 으로 뭉뚱그렸다면 프론트는 안내창을 띄울 수 없었을 것입니다.

**JSON 형식은 프롬프트로 강제하고 브라우저가 다시 검사합니다.** 모델이 코드펜스나
설명을 붙여 보내는 일이 있어, 프론트가 첫 `{` 와 마지막 `}` 사이만 잘라 파싱하고
실패하면 재시도 대상으로 넘깁니다.

## 2-4. 배포 후 발생한 문제를 어떤 순서로 진단하고 수정했는지(로그/콘솔/재배포) 설명할 수 있는가?

**순서**

```
① 배포 URL 에서 재현한다   ← 로컬에서도 재현되면 배포 문제가 아니다
② 층을 가른다              브라우저 콘솔 / Network 탭 / Vercel Functions 로그
③ 가장 작은 재현을 만든다  curl 한 줄로 되면 브라우저 변수를 다 지운 것
④ 고치고 push (자동 재배포) / 환경변수면 수정 후 반드시 Redeploy
⑤ 배포 URL 에서 다시 확인
```

②에서 어디를 볼지는 Network 탭이 정해 줍니다.

| 관찰 | 범인 | 볼 곳 |
|---|---|---|
| 요청이 아예 안 나감 | 프론트 JS | 브라우저 콘솔 |
| 요청은 나갔는데 4xx/5xx | 서버 함수 | Vercel Functions 로그 |
| 200 인데 화면이 이상 | 렌더링 | 브라우저 콘솔 |
| 빌드가 아예 안 됨 | 설정 | Vercel Build 로그 |

### 실제 사례 — 새 프로젝트의 빌드 실패

```
Build Failed
No python entrypoint found in default locations, but found potential entrypoints:
api/generate.py (variable: handler) api/me.py (variable: handler) ...
Add this to your pyproject.toml: [tool.vercel] entrypoint = "api.generate:handler"
```

**진단** — 루트에 `requirements.txt` 가 있어 Vercel 이 이 저장소를 "파이썬 앱 하나" 로
감지했습니다. 그래서 "앱의 진입점을 대라" 고 요구했습니다.

**여기서 오류가 시키는 대로 하면 안 됩니다.** 이 프로젝트는 앱이 아니라
정적 파일 + 함수 5개입니다. 진입점을 지정하면 **함수 다섯이 앱 하나로 뭉개져**
`/api/topics` 도 `/api/pdf` 도 사라집니다. 반대 방향으로 가야 합니다.

**수정** — `vercel.json` 에 프레임워크가 없음을 선언했습니다.

```json
{ "framework": null, "buildCommand": null, "outputDirectory": null, "installCommand": null }
```

대시보드에서 한 번 고르는 대신 저장소에 적었습니다. **다음에 누가 이 저장소를
임포트해도 같은 자리에서 막히지 않습니다.**

**재배포** — push 하면 Vercel 이 자동으로 다시 빌드합니다. 성공 후 배포 주소에서
`curl` 로 7가지를 확인했습니다.

**여기서 배운 것** — **오류 메시지는 증상을 정확히 알려 주지만 해법까지 맞지는
않습니다.** 그 메시지의 해법은 "이 저장소가 파이썬 앱이다" 라는 전제 위에 있었고,
그 전제가 틀렸습니다.

### 사례 — 환경변수는 재배포해야 반영된다

지금 배포본의 AI 생성이 실패하는 것도 같은 종류입니다.
코드는 정상이고 `OPENAI_API_KEY` 가 비어 있습니다. **값을 넣는 것만으로는 안 되고
Redeploy 를 해야** 함수가 새 값을 받습니다. 이걸 모르면
"분명히 넣었는데 왜 그대로지" 에서 한참을 헤맵니다.

# 항목 3 — 기초 개념 설명

## 3-1. HTML / CSS / JavaScript 의 역할 차이를 서비스 코드 예시를 근거로 설명할 수 있는가?

셋은 **책임지는 질문이 다릅니다.**
HTML 은 "무엇이 있는가", CSS 는 "어떻게 보이는가", JavaScript 는 "무엇이 일어나는가".

### 예시 1 — 결과 패널은 HTML 에 비어 있다

```html
<main class="main" id="main"></main>
```

브레인스토밍·아웃라인·어휘·에세이가 HTML 에 한 글자도 없습니다.
`app.js` 의 `renderMain()` 이 문자열로 만들어 넣습니다.
**내용이 데이터에 따라 달라지기 때문**입니다. 주제 165개도 마찬가지로 HTML 에 없고
`/api/topics` 로 받아 옵니다.

### 예시 2 — 섹션을 감추는 것은 CSS 가 한다

```javascript
// nav.js — JavaScript 는 클래스만 붙였다 뗀다
el.classList.toggle("is-active", id === active);
```

`el.style.display = "none"` 을 쓰지 않습니다. **인라인 스타일은 스타일시트를 이기므로,
한번 그렇게 감추면 나중에 CSS 로는 다시 못 보이게 됩니다.** 그래서 JavaScript 는
"어느 것이 활성인가" 라는 사실만 클래스로 남기고, 감추는 일은 CSS 에 맡깁니다.

### 예시 3 — 그런데 학년 색은 JavaScript 에 있다

```javascript
var GRADE_COLOR = { "Grade 1-2": { accent: "#C97B5A" }, ... };
```

**색이 데이터(학년)에 따라 달라지기 때문**입니다. 반대로 카드 사이 간격은 CSS 에만
있습니다. 데이터가 무엇이든 간격은 같습니다.

**그래서 기준은 "보이는 것이면 CSS" 가 아니라 "데이터에 따라 달라지면 JavaScript" 입니다.**

## 3-2. fetch 요청이 서버리스 함수로 전달되고 응답이 돌아오는 흐름을 설명할 수 있는가?

```
[브라우저]                                    [Vercel]              [OpenAI]

 버튼 클릭
   │
 상태 변경 → 화면 다시 그리기 (버튼 잠금)
   │
 프롬프트 조립 (학년 규칙 + JSON 스키마)
   │
 fetch("/api/generate", {method:"POST", body, signal})
   │                    ↑ 도메인이 없다 = 같은 서버
   └──────────────────────────────▶ api/generate.py 가 깨어난다
                                      ├ 입력 검증
                                      ├ 키 확인
                                      ├ 출처·레이트리밋
                                      ├ 크레딧 차감
                                      └────────────────────▶ Responses API
                                                                  │
                                      ◀───────────────────────────┘
                                      {"text": "..."}
   ◀──────────────────────────────┘
   │
 JSON 추출 → 학년 기준 검증
   │
   ├ 통과 → 화면에 그리고 localStorage 에 저장
   └ 미달 → 부족한 항목을 프롬프트에 붙여 다시 (최대 4회)
```

설명할 때 짚는 세 가지입니다.

**`/api/generate` 에 도메인이 없다는 것.** 같은 도메인이라 브라우저가 CORS 를 따지지
않고, 무엇보다 **OpenAI 주소가 브라우저에 전혀 등장하지 않습니다.** 브라우저가 아는
곳은 자기 서버뿐입니다.

**서버리스 함수는 이 요청 때만 깨어난다는 것.** 상시 서버가 아닙니다.
`api/generate.py` 안의 `class handler(BaseHTTPRequestHandler)` 를 Vercel 이 요청마다
깨워 `do_POST` 를 부릅니다. 요청이 끝나면 사라지므로 **이전 요청의 기억이 없습니다.**

**`await` 는 브라우저를 멈추지 않는다는 것.** 그 함수만 멈추고 브라우저는 계속 돕니다.
그래서 요청 전에 로딩 화면을 먼저 그려야 합니다. 그리고 응답이 영영 안 올 수도 있으므로
`AbortController` 로 75초 시한을 걸었습니다. 서버 함수 상한(60초)보다 길게 잡아,
서버가 먼저 끝낼 기회를 주고 그래도 소식이 없을 때 브라우저가 끊습니다.

## 3-3. 환경 변수를 쓰는 이유(보안 / 운영)를 설명할 수 있는가?

### 보안

**브라우저로 내려간 것은 전부 공개된 것입니다.** JavaScript 파일에 키를 적으면
개발자도구 Sources 탭에 그대로 보입니다. 변수 이름을 이상하게 짓거나 문자열을 쪼개
붙여도 실행되는 순간 원래 값으로 합쳐집니다. **난독화는 대책이 아닙니다.**

키가 새면 남이 내 계정으로 API 를 부르고 요금은 내 카드로 나갑니다.
그리고 이런 키는 사람이 찾지 않습니다. **봇이 공개 저장소를 훑으며 찾습니다.**

### 운영

보안만이 이유는 아닙니다. **같은 코드를 여러 환경에서 돌리기 위해서**이기도 합니다.

| | 로컬 | 배포 |
|---|---|---|
| `OPENAI_API_KEY` | 개발용 키 | 운영 키 |
| `ALLOWED_ORIGINS` | 비움 (검사 안 함) | 배포 도메인 |
| `RATE_LIMIT_GLOBAL_DAILY` | 넉넉히 | 150 |

값이 코드 안에 박혀 있으면 환경마다 코드를 고쳐야 하고, 상한 하나 바꾸려고
재배포가 아니라 **코드 수정**을 해야 합니다.

이 프로젝트는 여기서 한 걸음 더 나갔습니다. **환경변수가 없으면 그 계층이 스스로
꺼집니다.** Supabase 관련 값 셋이 비어 있으면 로그인·크레딧 계층 전체가 꺼지고
나머지는 그대로 돕니다(`/api/me` 가 `auth_enabled: false` 를 돌려줍니다).
설정을 다 갖추지 않아도 배포가 깨지지 않게 하려는 것입니다.

**`.env.example` 을 저장소에 두는 이유** — 값은 안 주고 **이름과 의미만** 알려 주기
위해서입니다. 이 파일이 없으면 받아 간 사람은 무슨 환경변수가 필요한지 알 수 없습니다.

## 3-4. AI 기능을 이 서비스에 넣은 이유와, 프롬프트(요청 내용)를 어떻게 구성했는지 설명할 수 있는가?

### 왜 넣었는가

초등 영어 라이팅 수업에서 강사가 겪는 병목은 "주제" 가 아니라
**"학년 기준에 맞는 모범 답안"** 입니다. 주제는 학원마다 이미 쌓여 있습니다.
모범 답안은 매번 강사가 직접 씁니다. 주제 하나·학년 하나에 20~30분이 듭니다.

그렇다고 일반 AI 챗봇에 주제를 넣으면 글은 나오는데 **분량과 문단 구조가 어긋납니다.**
초1-2 에게 200단어 4문단이 나오거나, 초5-6 에게 축약형이 섞인 구어체가 나옵니다.
사람이 단어를 세어 보고 다시 요청해야 하므로 결국 시간이 안 줄어듭니다.
그리고 레벨테스트는 정확히 이 기준으로 떨어뜨립니다.

**그래서 이 서비스가 푸는 문제는 "생성" 이 아니라 "기준 통과까지 생성" 입니다.**
AI 는 글을 쓰고, **기준 검사는 코드가 합니다.**

### 프롬프트 구성 — 네 겹

**1. 시스템 프롬프트 — 역할과 출력 형식을 고정**

```
당신은 AXISOLVE EDUTECH 의 초등 영어 라이팅 교재 콘텐츠 작성 엔진입니다.
사용자 메시지에 명시된 JSON 스키마를 정확히 따르는 JSON 객체 하나만 출력하십시오.
코드펜스, 설명, 인사말, 그 외 어떤 텍스트도 JSON 앞뒤에 포함하지 마십시오.
```

"인사말을 붙이지 마라" 를 명시한 것은, 안 적으면 `여기 요청하신 에세이입니다!` 를
앞에 붙여 JSON 파싱이 깨지기 때문입니다.

**2. 학년별 기준 — 코드의 상수를 문장으로**

```
Grade 1-2 : 총 60~80단어, 5~7문장. 단순 문장 중심. 3인칭 단수 s/es, 관사, 복수형을
            정확히 지킬 것. 축약형 허용.
Grade 3-4 : 총 100~130단어, 반드시 하나의 문단. Topic → Supporting → Closing.
Grade 5-6 : 총 180~220단어, 정확히 4문단. 포멀. 축약형 절대 금지.
            각 근거 뒤에 상술(Elaboration)을 반드시 포함.
```

같은 값이 검증 코드(`RUBRIC`)에도 상수로 있습니다. **프롬프트와 검사가 같은 기준을
보게 하려고 일부러 둘 다 둡니다.**

**3. 출력 스키마 — 학년마다 다르게**

에세이만 주면 베껴 쓰기가 됩니다. 그래서 브레인스토밍 질문·아웃라인·어휘/문형을
함께 요구합니다. 학생이 **따라 쓸 수 있는 재료**가 되어야 하기 때문입니다.

**4. 재시도 피드백 — 실패했을 때만 덧붙는 층**

이것이 핵심입니다. 검증에서 미달이면 **무엇이 어떻게 모자랐는지**를 문장으로 만들어
다음 요청에 붙입니다.

```
[이전 시도의 문제]
- 단어 수 47개 (목표 60~80)
- 문장 수 4개 (목표 5~7)
단어수가 목표 하한선에 크게 미달했습니다. 문장을 추가하거나 근거·묘사를 보강하여
이번에는 반드시 60단어 이상으로 작성하십시오.
```

"다시 써 줘" 가 아니라 **"몇 개였고 몇 개여야 한다"** 를 줍니다. 숫자를 주면 통과율이
확연히 다릅니다. 이 되먹임을 최대 4회 돌립니다.

**직접 입력 주제일 때만 붙는 규칙**도 있습니다. 한국어로 적어도 영어 에세이가 나오게 하고,
사용자가 적은 아이디어를 반드시 본문에 반영하게 합니다.

**자동 재시도는 크레딧을 더 차감하지 않습니다.** 4회를 호출해도 1크레딧입니다.
사용자가 잘못한 게 아니라 기계가 기준을 못 맞춘 것이기 때문입니다.

# 항목 4 — 가정 상황에 대한 판단

## 4-1. 만약 응답 지연이 잦다면(속도/비용/쿼터), 어떤 개선 옵션을 고려할지 설명할 수 있는가?

**먼저 원인을 가릅니다.** 지연은 한 가지가 아닙니다.

| 원인 | 확인 방법 |
|---|---|
| 모델 추론 자체가 김 | 시도 1회의 소요 시간 |
| **재시도가 반복됨** | `generation_sessions` 의 시도 횟수 분포 |
| 함수 콜드 스타트 | 첫 호출과 이후 호출의 차이 |
| 사용자 네트워크 | 응답 크기 대비 소요 시간 |

**대부분은 두 번째입니다.** 4회 재시도는 최악의 경우 소요 시간을 4배로 만듭니다.
그래서 **1회 통과율을 올리는 것이 지연과 비용을 동시에 줄이는 유일한 지점**입니다.

### 우선순위대로

**① 1회 통과율을 올린다 — 가장 효과가 크고 부작용이 없다**

지금은 미달했을 때만 숫자를 줍니다. 처음부터 "이전 학생 답안 예시" 를 한 편 넣거나,
분량 지시를 문장 수·문단 수로 더 구체화하면 첫 시도 통과율이 오릅니다.
**재시도 1회를 줄이면 지연도 비용도 같은 비율로 줄어듭니다.**

**② 학년별로 다른 모델을 쓴다**

실측 원가가 학년마다 크게 다릅니다 — 초1-2 약 1.6원, 초3-4 약 2.2원,
**초5-6 약 14.2원**(추론 토큰이 원가의 대부분). 초5-6 만 어렵고 나머지는 쉽습니다.
초1-2·3-4 는 저비용 모델(`gpt-5.6-luna`)로 내리고 초5-6 만 균형 모델을 씁니다.
`OPENAI_MODEL` 환경변수가 이미 있으므로 **코드 수정 없이** 바꿀 수 있습니다.

**③ 추론 강도를 낮춘다**

`OPENAI_REASONING_EFFORT` 를 `medium` → `low` 로. 초1-2 처럼 형식이 단순한 학년은
추론이 길 이유가 없습니다. 이것도 환경변수입니다.

**④ 스트리밍으로 바꾼다**

지금은 전부 받은 뒤에 그립니다. 스트리밍하면 **체감 지연**이 크게 줄어듭니다.
다만 이 서비스는 JSON 하나를 받아 검증하는 구조라, 스트리밍하면 검증을 마지막에만
할 수 있어 재시도 로직과 잘 안 맞습니다. **에세이 본문만 따로 스트리밍**하는
절충이 현실적입니다.

**⑤ 결과를 재사용한다**

같은 기출 주제 × 같은 학년 × 아이디어 없음 → 결과가 크게 다를 이유가 없습니다.
이 조합을 캐시하면 지연이 0 이 되고 비용도 0 입니다.
다만 "매번 다른 글" 을 기대하는 사용자와 충돌하므로, **"저장된 예시 보기" 와
"새로 생성" 을 나눠 주는 편**이 낫습니다.

**⑥ 재시도 상한을 4 → 2 로 줄이고, 미달분은 사람이 판단하게 한다**

이미 4회 미달 시 근접 결과 + 경고를 보여 주고 있습니다. 2회로 줄이면 최악의 지연이
절반이 되고, 사용자는 경고를 보고 다시 누를지 정하면 됩니다.
**측정 없이 먼저 하면 안 됩니다.** ①의 시도 횟수 분포를 보고, 3·4회에서 통과하는
비율이 낮으면 그때 줄이는 것이 맞습니다.

### 쿼터 쪽

429 가 잦다면 지연이 아니라 상한 문제입니다. 지금은 IP 시간당 12·일일 30·전역 일일 500 인데,
학원처럼 **공용 IP** 에서 여럿이 쓰면 IP 상한에 먼저 걸립니다.
이때는 IP 상한을 올리는 게 아니라 **로그인 기반 크레딧으로 전환**하는 것이 답입니다.
IP 는 사용자를 식별하는 수단으로 정확하지 않습니다.

### 지금 하지 않을 것

함수 `maxDuration` 을 60초 → 300초로 늘리는 것. **지연을 줄이는 게 아니라 참는 것**이고,
그만큼 사용자는 더 오래 기다립니다. 20초 안내와 75초 중단이 이미 있으므로,
늘려야 할 때는 초5-6 이 실제로 60초를 넘겨 잘리는 것이 로그로 확인될 때뿐입니다.

## 4-2. 만약 AI 기능을 2개로 늘린다면, 프론트/백엔드 구조를 어떻게 확장할지 설명할 수 있는가?

두 번째 기능은 **학생 답안 첨삭**이 될 것입니다. 지금 기획서에서 의도적으로 범위 밖에
둔 것이고, 학생이 쓴 글을 같은 루브릭으로 채점·수정하는 기능입니다.

### 지금 구조의 문제

`app.js` 한 파일 안에 **생성 기능 전용인 것들이 전역 상수로** 박혀 있습니다.

```javascript
var RUBRIC = {...};        // 학년별 기준
var SYSTEM_PROMPT = "...";  // 역할 고정
var MAX_ATTEMPTS = 4;
function buildPrompt(...)   // 프롬프트 조립
function assess(...)        // 검증
var loadingInfo = {};       // 학년별 로딩 상태
```

두 번째 기능을 그대로 얹으면 `SYSTEM_PROMPT_2`, `buildPrompt2`, `assess2` 가
같은 파일에 생깁니다. **어느 것이 어느 기능의 것인지 이름으로만 구분하게 되고,
셋째 기능에서 무너집니다.**

### 프론트 — 기능을 객체로 만든다

```
app.js            공통 (렌더 루프, 상태 관리, fetch 래퍼)
features/
  generate.js     { systemPrompt, buildPrompt, assess, render }
  review.js       { systemPrompt, buildPrompt, assess, render }
```

기능마다 **같은 모양의 객체 하나**를 내놓게 합니다. 공통 코드는 그 객체를 받아
똑같이 처리합니다. 재시도 루프·로딩 상태·오류 갈래 나누기는 기능이 달라도 **똑같으므로
공통으로 남습니다.** 실제로 지금 코드에서 기능마다 달라지는 것은
프롬프트·검증·렌더 셋뿐입니다.

상태 키도 바꿔야 합니다. 지금은 `loadingInfo[grade]` 인데
`loadingInfo[feature][grade]` 가 되어야 합니다. 생성 중에 첨삭을 누를 수 있어야 하니까요.

프레임워크 없이도 됩니다. 다만 `renderMain()` 이 `innerHTML` 을 통째로 갈아 끼우는
방식이라, 첨삭처럼 **긴 글을 입력받는 화면**이 생기면 다시 그릴 때마다 입력 포커스와
커서 위치를 잃습니다. **그때가 프레임워크를 검토할 시점**입니다(4-4 참조).

### 백엔드 — 함수를 나눈다

한 함수에 `task` 파라미터를 받아 갈래를 태우는 방법도 있지만, **나누는 쪽을 택합니다.**

```
api/generate.py    에세이 생성    maxDuration 60
api/review.py      답안 첨삭      maxDuration 30, 입력 크기 상한이 다름
api/_openai.py     ← 새로 뺀다 (클라이언트 생성, 호출, 오류 → HTTP 코드 변환)
api/_guard.py      그대로 공용
api/_supabase.py   그대로 공용
```

**나누는 이유**는 셋입니다.

1. `maxDuration`·메모리·입력 상한이 기능마다 다릅니다. 한 함수면 제일 무거운 쪽에
   맞춰야 하고, 가벼운 기능이 콜드 스타트 비용을 같이 뒤집어씁니다.
2. 한쪽이 실패해도 다른 쪽은 삽니다.
3. 로그와 사용량이 기능별로 갈립니다. 4-1 의 측정이 쉬워집니다.

공통 방어는 **이미 `_guard` `_supabase` 로 빠져 있어 그대로 재사용**됩니다.
이번 확장에서 새로 빼야 하는 것은 OpenAI 호출부(`_openai.py`)뿐입니다.
`vercel.json` 의 `functions` 에 새 항목과 `includeFiles` 를 추가하면 됩니다.

### 크레딧

기능마다 원가가 다르므로 단가도 달라야 합니다.
`credit_ledger` 의 사유 칸에 기능명을 남기고, 차감량을 기능별 상수로 둡니다.
지금 `consume_credit` 이 이미 사유를 받으므로 스키마 변경 없이 됩니다.

## 4-3. 만약 API 키가 유출되었다면, 즉시 취해야 할 조치와 재발 방지 방법을 설명할 수 있는가?

### 즉시 — 순서가 정해져 있습니다

```
① OpenAI 대시보드에서 그 키를 폐기(revoke)   ← 무조건 제일 먼저
② 새 키 발급
③ Vercel 환경변수 교체 → Redeploy
④ 사용량·청구서 확인 (유출 시점 이후 이상 호출)
⑤ 커밋 이력에서 제거 (git filter-repo 등) → 강제 푸시
⑥ 유출 경로 파악 (커밋? 스크린샷? 로그? 채팅?)
```

**④ 나 ⑤ 를 ① 보다 먼저 하면 안 됩니다.** 이력을 지우는 동안에도 그 키는 살아 있습니다.
그리고 공개 저장소에 올라간 키는 **봇이 몇 분 안에 가져갑니다.** 이미 복제되었다면
이력 삭제는 아무 소용이 없습니다. **무효화가 먼저이고 정리는 나중입니다.**

⑤ 를 아예 생략해도 되느냐 하면, 아닙니다. 폐기된 키라도 이력에 남아 있으면
"이 저장소는 키를 커밋한 적이 있다" 는 사실이 남고, 다음 사람이 그 패턴을 따라 합니다.

### 재발 방지 — 사람의 주의력에 기대지 않는 것부터

| 층 | 방법 | 이 저장소의 상태 |
|---|---|---|
| **커밋 자체를 막는다** | `.gitignore` 에 `.env` `.env.local` | ✅ 있음 |
| | `.env.example` 로 값 없이 이름만 공유 | ✅ 있음 |
| | pre-commit 훅으로 `sk-` 패턴 차단 | ⬜ 넣을 만함 |
| | GitHub **Push Protection** (푸시 자체를 거부) | ⬜ 켤 만함 |
| | GitHub **Secret Scanning** 알림 | ⬜ 켤 만함 |
| **키를 만질 일을 줄인다** | 로컬은 `.env.local`, 배포는 대시보드 | ✅ |
| | 프로젝트별로 키를 따로 발급 | ⬜ |
| **터져도 피해를 줄인다** | OpenAI **Budget limit** | ⬜ **반드시** |
| | 사용량 알림 (임계치 메일) | ⬜ |
| | `ALLOWED_ORIGINS` 로 출처 제한 | ⚠ 코드는 있고 값이 비어 있음 |
| | IP·전역 레이트리밋 | ✅ `api/_guard.py` |

**가장 중요한 것은 마지막 층입니다.** 앞의 두 층은 "실수하지 않으면" 이 전제인데
사람은 실수합니다. Budget limit 은 실수해도 손해의 상한을 정해 줍니다.

**그리고 짚어 둘 것** — 키가 안 새도 **엔드포인트가 열려 있으면 남이 그것을 부르고
요금은 똑같이 나옵니다.** 지금 이 배포본이 그 상태입니다. `ALLOWED_ORIGINS` 가 비어 있어
`curl` 로 `/api/generate` 를 아무나 부를 수 있습니다.
**키 관리와 엔드포인트 잠금은 다른 일이고 둘 다 해야 합니다.**

## 4-4. 만약 요구사항이 "프론트 프레임워크 허용" 으로 바뀐다면, 어떤 장단점과 변경 범위를 예상할 수 있는가?

### 결론부터 — 지금 규모에서는 안 바꿉니다

프론트 자바스크립트가 1,406줄이고, 화면 상태가 사실상 **주제 하나·학년 셋·로딩·오류** 다섯 개입니다.
이 정도는 프레임워크가 해결해 줄 문제가 없습니다.

### 그래도 얻는 것

**가장 큰 것은 부분 갱신입니다.** 지금 `renderMain()` 은 `innerHTML` 을 통째로
갈아 끼웁니다. 그래서 다시 그릴 때마다 **입력 포커스와 커서 위치, 스크롤이 날아갑니다.**
아이디어 입력칸이 짧아서 지금은 티가 안 나지만, 4-2 의 첨삭 기능처럼 **긴 글을
입력받는 화면**이 생기면 바로 문제가 됩니다.

그 밖에 — 컴포넌트 단위 재사용(학년 패널 3개가 지금은 같은 함수의 반복 호출),
상태와 화면의 동기화를 손으로 안 해도 되는 것, TypeScript 를 쓰면 타입 검사.
`assess()` 가 다루는 데이터가 "문자열일 수도 리스트일 수도" 였던 사고(PDF 어휘표 버그)는
타입이 있었으면 애초에 안 났습니다.

### 잃는 것

| 잃는 것 | 구체적으로 |
|---|---|
| **빌드 단계가 생긴다** | 지금은 "내가 쓴 파일 = 브라우저가 받는 파일". 디버깅에 번들·소스맵 해석이 낀다 |
| **배포 설정이 복잡해진다** | `vercel.json` 의 `buildCommand` `outputDirectory` 를 채워야 한다. 이번 빌드 실패가 프레임워크 자동 감지에서 나왔는데, 그 위험이 늘어난다 |
| **의존성이 생긴다** | 지금 프론트 의존성이 0 개. 버전 업·보안 패치·`node_modules` 관리가 따라온다 |
| **첫 로딩이 늘어난다** | 지금 브라우저가 받는 프론트 전체가 **128KB**(HTML+CSS+JS). 학원 공용 와이파이에서 쓰는 도구라 무시 못 한다 |
| **API 키 노출 경로가 는다** | `VITE_` 접두사 환경변수는 **번들에 그대로 박힙니다.** 서버 전용 값을 실수로 넣으면 그대로 공개됩니다. 지금 구조에는 이 함정이 아예 없습니다 |

마지막 항목이 제일 중요합니다. **프레임워크는 "환경변수처럼 생겼지만 브라우저로
내려가는 값" 이라는 새로운 실수 경로를 만듭니다.**

### 변경 범위

| 파일 | 어떻게 |
|---|---|
| `index.html` | 마운트 지점 하나만 남긴다 |
| `app.js` | 컴포넌트로 쪼갠다 — **가장 큰 작업** |
| `nav.js` | 라우터로 대체 (또는 그대로 둬도 됨) |
| `landing.js` `auth.js` | 컴포넌트화 |
| `styles.css` 등 | 거의 그대로. CSS Modules 로 갈지는 선택 |
| **`api/`** | **손대지 않는다** |
| `vercel.json` | `framework` `buildCommand` `outputDirectory` 를 채운다 |
| `.vercelignore` | 소스 폴더를 빼고 빌드 산출물만 올린다 |
| `dev_server.py` | 정적 파일 대신 빌드 산출물을 서빙하도록 |

**`api/` 가 그대로라는 점이 핵심입니다.** 프론트와 백엔드가 `/api/...` 라는 HTTP 경계로
갈려 있어, 프론트를 통째로 갈아도 서버는 영향이 없습니다.
**지금 구조를 이렇게 나눠 둔 값어치가 여기서 나옵니다.**
