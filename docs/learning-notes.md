# 설명문 — 이 과제를 통해 알게 된 것

과제 3절은 "학습자가 스스로 설명할 수 있어야 한다" 고 여섯 가지를 요구합니다.
그래서 이 문서는 요약표가 아니라 **설명문**입니다. 남이 물었을 때 그대로 말할 수 있게 썼습니다.

교과서에서 옮긴 정의는 넣지 않았습니다. 여섯 항목 전부 **이 프로젝트에서 실제로 겪은 일**
로 설명합니다. 그래야 제가 아는 것과 아는 척하는 것이 갈립니다.

만든 것은 **AXISOLVE Writing Engine** — 주제를 고르면 학년 합격 기준을 통과할 때까지
AI 가 다시 쓰는 영어 라이팅 서비스입니다.

## 1. HTML · CSS · JavaScript 는 각각 무엇을 하는가

### 설명

셋은 같은 화면을 만들지만 **책임지는 질문이 다릅니다.**

HTML 은 **"무엇이 있는가"** 에 답합니다. 제목이 있고, 버튼이 있고, 입력칸이 있다는 사실
그 자체입니다. CSS 는 **"어떻게 보이는가"** 에 답합니다. 그 버튼이 남색인지, 화면이
좁아지면 아래로 내려가는지입니다. JavaScript 는 **"무엇이 일어나는가"** 에 답합니다.
그 버튼을 눌렀을 때 서버를 부르고, 받은 것을 화면에 꽂는 일입니다.

이 구분이 왜 중요하냐면, **한 층이 다른 층의 일을 대신하기 시작하면 고칠 수 없게 되기
때문**입니다. 예를 들어 JavaScript 로 `element.style.display = "none"` 을 직접 써서
무언가를 감추면, 나중에 CSS 로 그것을 다시 보이게 만들 수 없습니다. 인라인 스타일이
스타일시트를 이기기 때문입니다. 그래서 감추는 일은 CSS 에 맡기고, JavaScript 는
클래스만 붙였다 뗍니다.

### 이 프로젝트에서

`index.html` 의 결과 패널은 **빈 껍데기**입니다.

```html
<main class="main" id="main"></main>
```

안에 들어갈 브레인스토밍·아웃라인·어휘·에세이는 HTML 에 한 글자도 없습니다.
전부 `app.js` 의 `renderMain()` 이 문자열로 만들어 넣습니다. 내용이 **데이터에 따라
달라지기 때문**입니다. 주제 165개도 마찬가지로 HTML 에 없고 서버에서 받아 옵니다.

반대로 **카드 사이 간격은 CSS 에만** 있습니다. 데이터가 무엇이든 간격은 같기 때문입니다.

섹션 전환도 이 원칙대로입니다. `nav.js` 는 섹션을 지우거나 만들지 않습니다.

```javascript
el.classList.toggle("is-active", id === active);
```

클래스 하나만 붙였다 뗍니다. 실제로 감추는 일은 CSS 가 합니다.

다만 학년별 색(`GRADE_COLOR`)은 JavaScript 에 두었습니다. 색이 **데이터(학년)에 따라
달라지기** 때문입니다. 규칙은 "보이는 것이면 무조건 CSS" 가 아니라
**"데이터에 따라 달라지면 JavaScript, 아니면 CSS"** 입니다.

> **한 줄로** — HTML 은 무엇이 있는지, CSS 는 어떻게 보이는지, JavaScript 는 무엇이
> 일어나는지를 맡습니다. 데이터에 따라 달라지는 것만 JavaScript 로 넘깁니다.

## 2. 사용자 입력이 fetch 요청이 되고, 응답이 화면에 돌아오는 흐름

### 설명

버튼을 누르는 것과 화면이 바뀌는 것 사이에는 **일곱 단계**가 있습니다.
이 사이가 비어 있으면 사용자는 "눌리긴 한 건가" 를 알 수 없습니다.

```
①  클릭         →  ②  상태 변경 + 다시 그리기   →  ③  요청 조립
                                                        ↓
⑦  화면 반영    ←  ⑥  검증 (미달이면 ③ 으로)  ←  ⑤  응답 파싱  ←  ④  fetch
```

여기서 가장 중요한 것은 **② 가 ④ 보다 먼저**라는 점입니다.

`fetch` 는 시간이 걸립니다. 그런데 `await fetch(...)` 는 **브라우저 전체를 멈추지
않습니다.** 그 함수 하나만 잠시 멈추고 브라우저는 계속 돕니다. 그래서 요청을 보내기
**전에** 버튼을 잠그고 "생성 중" 을 그려 두지 않으면, 화면은 아무 일도 없었던 것처럼
보입니다. 사용자는 한 번 더 누릅니다. 그러면 유료 API 가 두 번 호출됩니다.

### 이 프로젝트에서

```javascript
// ② 먼저 상태를 바꾸고 다시 그린다
loadingInfo[grade] = { attempt: 1, max: MAX_ATTEMPTS };
renderMain();                      // 버튼 잠금 + 스피너

// ④ 그다음에 요청을 보낸다
var res = await fetch("/api/generate", {
  method: "POST",
  headers: headers,
  signal: controller.signal,
  body: JSON.stringify({ prompt: prompt, system: SYSTEM_PROMPT })
});
```

⑤ 에서는 응답을 그냥 믿지 않습니다. AI 가 JSON 앞뒤에 설명을 붙여 보내는 일이 있어,
코드펜스를 걷어내고 첫 `{` 와 마지막 `}` 사이만 잘라 파싱합니다.

⑥ 이 이 서비스의 핵심입니다. 받은 글의 **단어 수·문장 수·문단 수·축약형을 기계가
직접 셉니다.** 학년 기준에 미달이면 부족한 항목을 문장으로 만들어 프롬프트에 붙여
③ 으로 되돌아갑니다. **최대 4회**까지 자동으로 다시 씁니다.

```javascript
for (var attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
  parsed = await callModel(buildPrompt(grade, doc, keywordsText, feedback), ctx);
  var a = assess(grade, parsed);              // 기계가 센다
  if (a.ok) return { data: parsed };          // 통과하면 끝
  feedback = { issues: a.issues, wc: a.wc };  // 미달 항목을 되먹인다
}
```

4회를 다 써도 미달이면 **가장 근접한 결과에 경고 배지를 붙여** 보여 줍니다.
조용히 실패하지 않는 것이 중요합니다.

⑦ 에서는 화면에 그리는 동시에 `localStorage` 에도 저장합니다. 새로고침해도 남습니다.

### 응답이 아예 안 오면

이번 과제를 하면서 이 부분이 비어 있는 것을 발견했습니다. 응답이 오지 않으면 화면이
"생성 중" 으로 **영원히** 남았습니다. 그래서 두 개의 시계를 달았습니다.

- **20초** — 끊지 않고 "응답이 평소보다 오래 걸리고 있습니다" 만 띄웁니다
- **75초** — `AbortController` 로 요청을 끊고 다시 시도하라고 안내합니다

75초로 잡은 데는 이유가 있습니다. 서버 함수의 실행 상한이 `vercel.json` 에 60초로
걸려 있습니다. 브라우저를 그보다 **짧게** 잡으면 서버는 정상 처리 중인데 브라우저만
먼저 포기합니다. **서버가 자기 판단으로 끝낼 기회를 먼저 주고, 그래도 아무 말이 없을
때 브라우저가 끊는** 순서여야 합니다.

> **한 줄로** — 상태를 먼저 바꿔 그리고, 요청을 보내고, 응답을 검증한 뒤 화면에
> 반영합니다. `await` 는 브라우저가 아니라 그 함수만 멈춥니다.

## 3. Vercel Serverless Functions 와, 프론트가 백엔드를 부르는 구조

### 설명

**서버리스 함수는 상시 켜져 있는 서버가 아닙니다.** 요청이 올 때만 깨어나 응답하고
사라지는 함수 하나입니다.

이 차이가 실제로 무엇을 바꾸느냐면, **아무도 안 쓰면 비용이 0** 입니다. 서버를 빌리면
접속자가 없어도 매달 냅니다. 그리고 관리할 것이 없습니다. 운영체제 업데이트도,
프로세스가 죽었는지 지켜보는 일도 없습니다.

대신 제약이 생깁니다. 함수는 매번 새로 깨어나므로 **이전 요청의 기억이 없습니다.**
그래서 이 프로젝트의 레이트리밋 카운터가 정확한 과금 장치가 못 됩니다. 카운터가 함수
인스턴스 메모리에 있는데, 인스턴스가 여러 개면 상한이 그만큼 곱해지고 재활용되면
초기화됩니다. **폭주 차단 장치이지 정확한 계량기가 아닙니다.** 정확한 계량은 DB
(이 프로젝트에서는 Supabase 의 `credit_ledger`)가 맡습니다.

### Vercel 의 규칙

**`api/` 폴더의 파일 하나가 곧 주소 하나입니다.** 라우터를 쓰지 않습니다.

| 파일 | 주소 |
|---|---|
| `api/generate.py` | `POST /api/generate` |
| `api/topics.py` | `GET /api/topics` |
| `api/pdf.py` | `POST /api/pdf` |
| `api/me.py` | `GET /api/me` |
| `api/redeem.py` | `POST /api/redeem` |
| `api/_guard.py` · `api/_supabase.py` … | **주소 없음** |

`_` 로 시작하는 파일은 여러 함수가 같이 쓰는 **공용 모듈**이지 엔드포인트가 아닙니다.
`vercel.json` 의 rewrites 로 `/api/_*` 를 404 로 막았습니다. 안 막으면 서버 코드가
그대로 읽힙니다.

파이썬 함수는 이렇게 생겼습니다.

```python
class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        ...
```

Vercel 이 요청마다 이 클래스를 깨워 `do_POST` 를 부릅니다.

### 프론트가 부르는 쪽

```javascript
await fetch("/api/generate", { ... })
```

**주소에 도메인이 없다**는 점이 핵심입니다. 같은 도메인이라 브라우저가 CORS 를 따지지
않고, 무엇보다 **OpenAI 주소가 브라우저에 전혀 등장하지 않습니다.** 브라우저가 아는
것은 자기 서버뿐입니다. OpenAI 호출은 전부 `api/generate.py` 안에서 일어납니다.

```
[브라우저]  ──  POST /api/generate  ──▶  [api/generate.py]  ──▶  [OpenAI]
                                              ↑
                                    OPENAI_API_KEY 는 여기에만 있다
```

### 로컬에서 같은 구조를 재현하기

`dev_server.py` 를 만들어 이 규칙만 흉내냈습니다. `api/<이름>.py` 의 `handler` 를
찾아 부르고, `_` 로 시작하는 파일과 배포 제외 경로를 로컬에서도 404 로 막습니다.

만들면서 한 번 틀렸습니다. 처음에는 이렇게 했습니다.

```python
fn = getattr(handler_cls, "do_" + method)
fn(self)                      # ← 메서드만 빌려 온다
```

그러자 500 이 났습니다.

```
AttributeError: 'DevHandler' object has no attribute '_read_json'
```

함수 파일들이 `self._read_json()` 처럼 **자기 클래스의 헬퍼**를 쓰기 때문입니다.
메서드만 빌려 오면 그 헬퍼가 따라오지 않습니다. `__init__` 없이 그 클래스의 객체를
만들고, 요청의 인스턴스 딕셔너리를 공유시켜 고쳤습니다.

```python
proxy = object.__new__(handler_cls)
proxy.__dict__ = self.__dict__       # rfile·wfile·headers 를 그대로 공유
getattr(proxy, "do_" + method)()
```

> **한 줄로** — `api/` 의 파일 하나가 주소 하나이고, 요청이 올 때만 깨어납니다.
> 프론트는 도메인 없는 `/api/...` 만 부르므로 AI 제공자의 주소도 키도 모릅니다.

## 4. 왜 API 키를 환경 변수로 관리해야 하는가

### 설명

**브라우저로 내려간 것은 전부 공개된 것입니다.**

이 한 문장이 전부입니다. JavaScript 파일에 키를 적으면 개발자도구 Sources 탭에서
그대로 보입니다. 변수 이름을 이상하게 짓거나 문자열을 쪼개 붙여도 소용없습니다.
실행되는 순간 원래 값으로 합쳐지고, Network 탭에는 요청 헤더가 그대로 찍힙니다.
**난독화는 대책이 아닙니다.**

키가 새면 남이 내 계정으로 API 를 호출합니다. 요금은 내 카드로 나갑니다.
그리고 이런 키는 사람이 찾지 않습니다. **봇이 공개 저장소를 훑으며 찾습니다.**

### 이 프로젝트에서 키가 없는 곳

| 장소 | 키 | 이유 |
|---|---|---|
| Git 저장소 | ❌ | `.gitignore` 에 `.env` `.env.local` |
| 브라우저로 내려가는 파일 | ❌ | 프론트는 `/api/generate` 만 부른다 |
| API 응답 본문 | ❌ | 서버는 `{"text": "..."}` 만 돌려준다 |
| **Vercel 환경변수** | ✅ | 함수가 실행될 때만 `os.environ` 으로 읽는다 |

확인은 명령 한 줄로 됩니다.

```bash
git grep -nE "sk-[A-Za-z0-9]{20,}"     # 결과 없음
```

### `.env.example` 을 저장소에 두는 이유

값은 안 주고 **이름과 의미만** 알려 주기 위해서입니다.

```
OPENAI_API_KEY=sk-...
# ALLOWED_ORIGINS=https://your-app.vercel.app
```

받아 간 사람은 `cp .env.example .env.local` 후 자기 값을 채웁니다.
이 파일이 없으면 "무슨 환경변수가 필요한지" 를 알 방법이 없습니다.

### 키가 새면 — 순서가 중요합니다

1. **OpenAI 대시보드에서 그 키를 즉시 폐기**
2. 새 키 발급
3. Vercel 환경변수 교체 후 **재배포**
4. 커밋 이력에서 제거 후 강제 푸시
5. 사용량·청구서 확인

**4번을 먼저 하면 안 됩니다.** 이력을 지우는 동안에도 그 키는 살아 있습니다.
이미 봇이 가져갔다면 이력 삭제는 아무 소용이 없습니다. **폐기가 언제나 먼저입니다.**

### 키만 막으면 끝이 아니다

키를 숨겨도 **내 서버의 엔드포인트가 열려 있으면** 남이 그것을 부릅니다.
요금은 똑같이 나갑니다. 그래서 `ALLOWED_ORIGINS` 로 출처를 검사합니다.

```bash
curl $URL/api/topics                                  # 403  ← Origin 없음
curl -H "Origin: $URL" $URL/api/topics                # 200
curl -H "Origin: https://evil.example" $URL/api/topics # 403
```

**403 이 나오는 것이 정상입니다.** 브라우저는 `Origin` 을 자동으로 붙이므로 실제
사용자에게는 아무 영향이 없고, 스크립트로 부르는 쪽만 막힙니다.

그 위에 IP 시간당 12회 · 일일 30회 · 전역 일일 500회 상한을 두고, 최종 방어선으로
OpenAI 계정에 **Budget limit** 을 겁니다. 이 서비스는 생성 한 번이 자동 재시도로
최대 4회 호출이 될 수 있어 상한이 특히 중요합니다.

> **한 줄로** — 브라우저로 내려간 것은 공개된 것이므로 키는 서버 환경변수에만 둡니다.
> 키를 숨기는 것과 엔드포인트를 잠그는 것은 **다른 일이고 둘 다 해야 합니다.**

## 5. 로컬과 배포는 무엇이 다르고, 문제가 나면 어떻게 고치는가

### 설명

같아 보이지만 다릅니다. 이 프로젝트에서 실제로 어긋났던 것들입니다.

| 항목 | 로컬 | 배포(Vercel) |
|---|---|---|
| 환경변수 | `.env.local` 파일 | 대시보드에 등록 |
| 반영 시점 | 서버 재시작 | **재배포 시점** |
| 파일 | 폴더에 있는 것 전부 | `.vercelignore` 에 적힌 것은 **안 올라감** |
| 실행 시간 | 무제한 | `maxDuration` (생성 60초) |
| 인스턴스 | 하나 | 여러 개일 수 있음 |
| 한글 폰트 | 시스템에 있음 | **없음** → 저장소에 동봉해야 PDF 한글이 찍힘 |

특히 **환경변수는 재배포 시점에 함수로 전달됩니다.** 값만 고치고 Redeploy 를 누르지
않으면 함수는 계속 옛 값을 봅니다. "분명히 바꿨는데 왜 그대로지" 의 대부분이 이것입니다.

### 가장 흔한 사고 — "로컬은 되는데 배포하면 404"

`.vercelignore` 로 제외한 파일이 로컬에는 그대로 있기 때문에 생깁니다.
이 프로젝트는 `topics.json`(출제 학원명 포함)·`docs/`(원가 자료)·`tools/` 를 제외합니다.

그래서 `dev_server.py` 가 **같은 목록을 로컬에서도 404 로 막습니다.**

```python
BLOCKED_PREFIXES = ("/topics.json", "/docs/", "/supabase/", "/tools/", ...)
```

로컬에서 미리 틀리게 만들어, 배포한 뒤에 발견하지 않도록 하는 장치입니다.

### 배포 후 문제를 고치는 흐름

```
① 배포 URL 에서 증상을 재현한다        ← 로컬에서도 재현되면 배포 문제가 아니다
② Vercel > Deployments > Functions 로그를 본다
③ 원인을 가른다
     코드      → 고쳐서 git push   → Vercel 이 자동 재배포
     환경변수  → 값 수정           → 반드시 Redeploy
     파일 누락 → .vercelignore 확인 → 고쳐서 push
④ 배포 URL 에서 다시 재현해 본다
```

### 이번에 실제로 겪은 것

새 Vercel 프로젝트를 만들었더니 빌드가 실패했습니다.

```
No python entrypoint found in default locations, but found potential entrypoints:
api/generate.py (variable: handler) api/me.py (variable: handler) ...
Add this to your pyproject.toml: [tool.vercel] entrypoint = "api.generate:handler"
```

루트에 `requirements.txt` 가 있으니 Vercel 이 이 저장소를 **"파이썬 앱 하나"** 로 잡고
"앱의 진입점을 대라" 고 한 것입니다.

**여기서 오류 메시지가 시키는 대로 하면 안 됩니다.** 이 프로젝트는 앱이 아니라
정적 파일 + 함수 5개입니다. 진입점을 지정하면 **함수 다섯이 앱 하나로 뭉개져**
`/api/topics` 도 `/api/pdf` 도 사라집니다. 반대 방향으로 가야 합니다.

```json
{ "framework": null, "buildCommand": null, "outputDirectory": null }
```

`vercel.json` 에 "프레임워크 없음" 을 박아 넣었습니다. 대시보드에서 한 번 고르는 것보다
저장소에 적어 두는 편이 낫습니다. **다음에 누가 이 저장소를 임포트해도 같은 자리에서
막히지 않습니다.**

**오류 메시지는 증상을 정확히 알려 주지만, 해법까지 맞는 것은 아닙니다.**
메시지가 제안한 해법은 "이 저장소가 파이썬 앱이다" 라는 전제 위에 있었고,
그 전제가 틀렸습니다. 이번에 가장 크게 배운 것입니다.

> **한 줄로** — 배포에는 없는 파일과 없는 폰트가 있고, 환경변수는 재배포해야 반영됩니다.
> 로컬 서버가 배포와 같은 것을 막아 주면 그 차이를 배포 전에 잡을 수 있습니다.

## 6. AI 가 만든 코드에서 오류 원인을 찾고 고치기

### 설명

**AI 코딩 도구를 쓴다고 디버깅이 사라지지 않습니다. 오히려 내가 안 쓴 코드라서 더
읽어야 합니다.**

AI 가 내는 오류에는 사람과 다른 경향이 있습니다. 문법은 거의 틀리지 않습니다.
대신 **문맥을 놓칩니다.** 앞에서 정한 것을 뒤에서 잊고, 같은 데이터의 형태가
두 갈래인 것을 모릅니다. 그래서 **문법 검사로는 하나도 안 잡히는 오류**가 나옵니다.

이 프로젝트에서 겪은 세 건입니다.

### 사례 1 — 생성이 전부 실패했다

직접 입력 주제 기능을 붙인 뒤 **모든** 생성이 실패했습니다.
`node --check app.js` 는 통과했습니다. 문법은 맞았기 때문입니다.

브라우저 콘솔에 답이 있었습니다.

```
ReferenceError: customNote is not defined
```

AI 가 `customNote` 를 **쓰는 쪽만 넣고 선언을 빠뜨린** 것입니다.
파싱은 통과하고 실행할 때 터집니다.

여기서 고치고 끝내지 않았습니다. **같은 종류가 또 나올 것**이라고 보고
`tools/smoke_app.js` 를 만들었습니다. 최소한의 DOM 을 흉내내 `app.js` 를 실제로
실행하고 핵심 함수를 호출해 봅니다. 수정 전 코드에 돌려서 이 버그를 진짜로
잡는 것까지 확인했습니다. 지금은 13항목을 돌립니다.

### 사례 2 — 에러 없이 조용히 틀렸다

PDF 어휘표에 `perspective: 관점` 이 **`p` 와 `e`** 로 찍혔습니다.

같은 필드인데 출처에 따라 형태가 달랐습니다.

```
app.js 가 AI 에게 요구한 스키마 :  "단어: 뜻"      ← 문자열
손으로 만든 샘플 JSON            :  ["단어", "뜻"]  ← 리스트
```

렌더러가 `w[0]`, `w[1]` 로 꺼냈습니다. 리스트면 "단어"·"뜻" 이 나오지만
**문자열이면 첫 글자와 둘째 글자**가 나옵니다.
문자열도 리스트도 `[0]` 이 되므로 파이썬은 아무 말도 하지 않았습니다.

`as_pair()` 로 두 형태를 먼저 정규화한 뒤에 쓰도록 고쳤습니다.

**이 종류가 제일 위험합니다.** 터지는 오류는 어차피 발견됩니다.
조용히 틀리는 것은 인쇄해서 학생에게 나눠 준 다음에 발견됩니다.

### 사례 3 — 내 PC 에만 있었다

이번 과제를 준비하며 `git clone` 을 새 폴더에 받아 README 대로 따라 해 봤습니다.
README 는 `py dev_server.py` 로 실행하라는데 **그 파일이 저장소에 없었습니다.**

`.gitignore` 에 `dev_server.py` 가 적혀 있어 한 번도 커밋된 적이 없었습니다.
**내 PC 에는 있으니 나만 몰랐습니다.**

이 종류는 코드를 아무리 읽어도 안 보입니다.
**받아 간 사람 입장이 되어 보는 것** 말고는 방법이 없습니다.

### 오류를 만났을 때 제가 따르는 순서

**1. 증상을 한 문장으로 적는다.**
"안 된다" 가 아니라 "Grade 5-6 에서만 어휘표 첫 글자만 나온다" 입니다.
이 문장을 못 쓰면 아직 증상을 모르는 것입니다.

**2. 어느 층인지 가른다.**
개발자도구 Network 탭을 엽니다.

| 관찰 | 범인 |
|---|---|
| 요청이 아예 안 나감 | 프론트 JavaScript |
| 요청은 나갔는데 4xx / 5xx | 서버 함수 |
| 200 인데 화면이 이상함 | 렌더링 |

**3. 로그를 본다.** 로컬은 콘솔, 배포는 Vercel 의 Functions 로그.

**4. 가장 작은 재현을 만든다.**
`curl` 한 줄로 재현되면 브라우저 쪽 변수를 전부 지운 것입니다.

```bash
curl -X POST $URL/api/generate -H "Content-Type: application/json" -d '{"prompt":""}'
# {"error": "생성 요청이 비어 있습니다. 주제를 선택한 뒤 다시 시도해 주십시오."}
```

**5. 고친 뒤 회귀 테스트를 돌린다.** `node tools/smoke_app.js`

### AI 에게 묻는 법

**"고쳐 줘" 는 잘 안 듣습니다.** AI 는 코드를 보고 그럴듯한 수정을 내놓는데,
원인이 다른 곳이면 멀쩡한 코드를 바꿔 놓습니다.

대신 이렇게 묻습니다.

> 이 증상, 이 코드, 이 로그다. **원인 후보를 대라.**

원인을 제가 고르면 고치는 것은 오히려 쉽습니다.
**판단은 제가 하고, 타이핑을 AI 가 합니다.** 반대가 되면 고칠 수 없는 코드가 쌓입니다.

> **한 줄로** — AI 가 내는 오류는 문법이 아니라 문맥에서 나옵니다.
> 증상을 한 문장으로 적고, 층을 가르고, 가장 작은 재현을 만들면
> 원인은 제가 찾을 수 있습니다. AI 에게는 해법이 아니라 후보를 물어야 합니다.
